Book-inator became successful because you defined what it is and what it is not.

Paper-inator should have a similar constitution.

Paper-inator Constitution (Draft)
Purpose

Paper-inator exists to collect, organize, read, annotate, connect, and cite academic knowledge sources in a unified and researcher-friendly environment.

Core Principles
1. User Owns Their Data

All references, notes, annotations, and projects remain accessible in open formats.

No vendor lock-in.

2. Research First

Academic workflows take priority over social features, feeds, and engagement mechanics.

3. Local First

Core functionality must work without cloud services.

Cloud functionality is optional.

4. Reversible Operations

Imports, metadata updates, and bulk operations should be recoverable whenever practical.

This aligns perfectly with your Book-inator philosophy.

5. Open Exchange

Support standards whenever possible:

BibTeX
RIS
DOI
CSL
PDF
6. Transparent Automation

Automatic metadata changes must be reviewable.

The user should always know:

What changed
Why it changed
How to restore it
7. Modular Design

Paper-inator must function independently while integrating cleanly with the central Hub.

No dependencies on unrelated modules.
