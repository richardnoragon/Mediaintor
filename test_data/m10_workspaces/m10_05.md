# M10-05 — failure paths, async restore and monitor recovery

**Implementation and automated verification COMPLETE; installed KDE acceptance remains M10-07. M10-G OPEN.** No installed environment upgraded.

## Implemented protections

- Restore transaction captures prior structure/context and suppresses intermediate Last Session writes. Commit waits for catalog success even when no selected book is saved.
- Generation tokens plus expected panel identity reject stale success/failure callbacks. Concurrent restores and management changes are rejected, not silently queued.
- Catalog failure or 35-second timeout aborts restoration and restores previous layout/context. Library changes or module-close requests cancel a pending restore before proceeding; the user explicitly retries that action. Shutdown cancels a pending transaction before snapshot persistence.
- Named snapshots remain untouched. Failed settings/workspace commits trigger structural rollback; metadata already committed and shared filters are never rolled back. Rollback failure disables further automatic mutation and reports the need for attention.
- Partial/failed metadata saves leave restoration blocked. Existing editor review remains authoritative; Cancel retains the current layout. Readers are never closed/launched/repositioned by restoration.
- Invalid Qt geometry uses the validated rectangle fallback. Available-screen clamping handles negative monitor coordinates, oversized/off-screen windows and missing saved screens. Runtime screen add/remove and available-geometry changes schedule recovery; named snapshots are not rewritten.
