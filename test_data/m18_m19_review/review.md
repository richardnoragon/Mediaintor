## Findings

### P1 — Cancel can discard an earlier draft before the close operation is confirmed

`mediainator/paper_ui.py:928` reviews editors sequentially. `DraftEditor.review` immediately saves or discards each choice. With two dirty drafts, choose Discard for the first and Cancel for the second: close is cancelled but the first draft is already discarded. Reproduced in `reproduce_findings.py` and `findings_reproduced.json`.

At suite level, `mediainator/window.py:945` likewise calls Paper, Music, Movie and Book close reviews sequentially. This conflicts with Hub constitution section 6: combined review, with pending save/discard choices unapplied until confirmation. A fix must collect decisions first across all affected drafts/modules, then apply only after final confirmation. Merely moving the module order cannot fix the loss.

### P1 — Recovery removes staging content before validating library ownership

`mediainator/paper_store.py:1244` removes all `.staging/*.part` files before calling `_read`, which checks schema and owning profile. Calling `recover()` through a store constructed with another valid profile ID deletes a staging file and then refuses the foreign library. Reproduced using disposable files. UI reload calls recovery at `paper_ui.py:410`.

Recovery must validate ownership and catalog compatibility before any filesystem mutation. It also needs operation ownership/locking: a staging file's existence alone does not prove that it is abandoned, so another active import's staging content must not be removed on reload.

### P2 — Large managed imports still copy on the UI thread

`mediainator/paper_ui.py:2427` applies imports synchronously; calls at lines 2451/2455 reach the copy in `paper_store.py:718`. The technical overview requires long-running copying away from the UI thread. The milestone design already acknowledges this limitation, but it remains a responsiveness gap: Stop cannot interrupt a long individual copy through the blocked event loop. Move copying to a coordinated worker and preserve cancellation/revalidation/transaction boundaries. This is a code-path finding, not a measured large-file benchmark.
